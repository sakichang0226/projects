# ECサイト アプリケーション要件定義

## プロジェクト概要

ポートフォリオ用ECサイトアプリケーション。
広告系商品の閲覧からカート・注文までの一連のEC機能を提供する。

参考: https://sakichang0226.github.io/profile/

画面デザイン: [docs/previews/index.html](previews/index.html)

アーキテクチャ図: [docs/architecture.drawio](architecture.drawio)

## 技術スタック

| 項目            | 内容                                       |
| --------------- | ------------------------------------------ |
| フロントエンド  | React + TypeScript + Vite                  |
| UIライブラリ    | Tailwind CSS + Headless UI                 |
| ルーティング    | React Router                               |
| 状態管理        | React Context（カート・認証）              |
| API通信         | axios                                      |
| バックエンド    | Java 17 + SpringBoot 3.x                   |
| セキュリティ    | Spring Security（JWT認証フィルター）       |
| 実行環境        | ECS (Fargate)                              |
| APIゲートウェイ | API Gateway (HTTP API) + Cloud Map         |
| 認証方式        | JWT（ステートレス、有効期限: 1時間）        |
| DB              | DynamoDB                                   |
| ストレージ      | S3（商品画像・フロントエンドホスティング） |
| コンテナ        | Docker                                     |
| CI/CD           | CodeBuild + CodePipeline                   |
| ビルドツール    | Gradle                                     |

### バックエンドアーキテクチャ

```
[CloudFront] ──→ [S3] (フロントエンド配信)
     │
     └──→ [API Gateway (HTTP API)] ──→ [VPCリンク] ──→ [Cloud Map] ──→ [ECS Fargate (SpringBoot)] ──→ [DynamoDB]
                                                                                    │
                                                                                    └──→ [S3] (商品画像)
```

| コンポーネント         | 役割                                                               |
| ---------------------- | ------------------------------------------------------------------ |
| CloudFront             | CDN配信・HTTPS終端                                                 |
| S3                     | フロントエンドホスティング・商品画像保存                           |
| API Gateway (HTTP API) | APIルーティング・HTTPS終端・スロットリング（従量課金でコスト最小） |
| VPCリンク              | API GatewayからプライベートサブネットのECSへ接続                   |
| Cloud Map              | ECSタスクのサービスディスカバリ（DNS名の自動登録）                 |
| ECS Fargate            | SpringBootアプリケーション実行（コンテナ）                         |
| Spring Security        | JWT認証フィルター・エンドポイント保護                              |
| DynamoDB               | データ永続化（商品・注文・ユーザー）                               |
| CodePipeline           | ソースからデプロイまでの自動化                                     |
| CodeBuild              | Gradleビルド・Dockerイメージ作成・ECRプッシュ                      |

### コスト最適化の設計判断

| 項目 | 判断理由 |
| ---- | -------- |
| ALBを不採用 | タスク1台構成でロードバランシング不要。ALB固定費（約$16〜22/月）を削減 |
| API Gateway (HTTP API) を採用 | 従量課金（100万リクエスト/$1）でポートフォリオ規模ならほぼ無料 |
| Cloud Map を採用 | ECSサービスディスカバリでタスクIP変動を吸収。追加コストなし |

### API エンドポイント一覧

| メソッド | パス            | 概要                   | 認証 |
| -------- | --------------- | ---------------------- | ---- |
| POST     | `/login`        | ログイン（JWT発行）    | 不要 |
| GET      | `/products`     | 商品一覧取得           | 不要 |
| GET      | `/products/:id` | 商品詳細取得           | 不要 |
| POST     | `/orders`       | 注文作成（決済スタブ） | 必要 |
| GET      | `/orders`       | 注文履歴取得           | 必要 |

### UIライブラリ役割分担

| ライブラリ               | 役割                                                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| Tailwind CSS             | レイアウト、グリッド、レスポンシブ、スペーシング、カラー、タイポグラフィ、ボタン・入力等の基本スタイル |
| Headless UI (Menu)       | ヘッダーのユーザードロップダウンメニュー                                                               |
| Headless UI (Disclosure) | 注文履歴のアコーディオン（注文明細の展開/折畳）                                                        |
| Headless UI (Transition) | トースト通知のフェードインアニメーション                                                               |
| Headless UI (Dialog)     | 確認モーダル（必要に応じて）                                                                           |

### 制約事項

- Tailwind CSS + Headless UI を使い画面をデザインすること
- 将来的に管理画面を追加する場合も同じスタックで統一すること
- 高機能テーブルが必要になった場合は TanStack Table を部分導入すること
- 決済処理はスタブ（常に成功を返す）
- 認証が必要な画面は未認証時にログイン画面へリダイレクト
- カートはフロントエンドのReact Context + localStorageで完結する。バックエンドにカートAPIは設けない。注文確定時にカート内容を `POST /orders` のリクエストボディとして送信する
- カートに入れられる商品は最大20種類までとする（BatchGetItemの100件制限を考慮し、実運用上の現実的な値として設定）

| 遷移元       | アクション                  | 遷移先               | 条件     |
| ------------ | --------------------------- | -------------------- | -------- |
| TOP画面      | 商品カードクリック          | 商品詳細画面         | —        |

| ヘッダー     | カートアイコンクリック      | カート画面           | —        |
| カート画面   | 注文手続きへ進む            | 注文確定画面         | 認証済み |
| カート画面   | 注文手続きへ進む            | ログイン画面         | 未認証   |

| 注文完了     | 注文履歴を見る              | 注文履歴画面         | —        |
| ヘッダー     | ユーザーメニュー > 注文履歴 | 注文履歴画面         | 認証済み |
| ヘッダー     | ログアウト                  | TOP画面              | —        |
| ログイン画面 | ログイン成功                | 遷移元の画面         | —        |

## 機能要件

### 共通

#### ヘッダー
- ロゴ（クリックでTOPへ）
- カートアイコン（バッジで数量表示）
- 未認証: 「ログイン」リンク
- 認証済み: ユーザー名ドロップダウン（注文履歴・ログアウト）

#### フッター
- コピーライト表示

### 1. TOP画面

- ヒーローバナー（カルーセル）で広告・プロモーションを表示
- 「おすすめ商品」「新着商品」セクションに商品カードをグリッド表示
  - PC: 4列 / タブレット: 3列 / SP: 2列
- 商品カードクリックで商品詳細画面へ遷移

### 2. 商品詳細画面

- URLパラメータ（商品ID）から商品情報を取得・表示
- 表示項目: 商品画像、商品名、価格（税込）、レーティング、商品説明（スペック情報含む）
- パンくずリスト: TOP > カテゴリ名 > 商品名
- 数量選択: 最小1、最大は在庫数（stock）。上限到達時は+ボタンを無効化
- カート追加ボタン押下でカートに商品を追加し、トースト通知を表示
- 在庫・ステータス制御:
  - `stock === 0` または `status === "S"（販売停止）` / `status === "D"（削除済み）` の場合、カート追加ボタンを無効化
  - ボタン無効時は「在庫切れ」「販売終了」等のラベルに切り替え、グレーアウト表示
  - 在庫残りわずか（stock <= 5 かつ stock > 0）の場合、「残りわずか」ラベルを表示
- エラーハンドリング:
  - 404（商品が見つからない）: 「お探しの商品は見つかりませんでした。削除されたか、URLが間違っている可能性があります。」メッセージ + 「TOPへ戻る」リンクを表示
  - 500等のサーバーエラー: 汎用エラーメッセージ + 再読み込みボタン / TOPへ戻るリンクを表示

### 3. カート画面

- カート内商品の一覧表示（商品画像、商品名、単価、数量、小計）
- 数量変更（増減ボタン）で即時合計再計算。最小1、最大は在庫数（stock）。上限到達時は+ボタンを無効化
- 削除ボタンで商品をカートから即時削除
- 合計金額（税込）を表示
- 「注文手続きへ進む」ボタンで注文確定画面へ遷移
  - 未ログイン時はログイン画面へリダイレクト
- カートが空の場合は空メッセージと「お買い物を続ける」リンクを表示
- カートはフロントのContext + localStorageで管理（バックエンドのカートAPIは不要）

### 4. 注文確定画面

- 認証ガード: 未認証ユーザーはログイン画面へリダイレクト
- カート内容を注文明細として表示（商品名、数量、小計）
- 小計・送料・合計を表示
- 「注文を確定する」ボタンで決済スタブAPIを呼び出し
  - 決済スタブは常に成功を返す
- 注文成功後:
  - 注文番号を数値形式で表示
  - カートをクリア
  - 「TOPへ戻る」「注文履歴を見る」リンクを表示
- エラーハンドリング:
  - エラーコード別にユーザー向け文言を出し分ける
  - API_ORDER_ERR001: 「カート内の商品が見つかりませんでした。商品が削除された可能性があります。」＋ カート画面へ戻るリンク
  - API_ORDER_ERR002: 「カート内に現在購入できない商品が含まれています。」＋ カート画面へ戻るリンク
  - API_ORDER_ERR003: 「在庫が不足している商品があります。数量をご確認ください。」＋ カート画面へ戻るリンク
  - API_ERR999 / その他: 「システムエラーが発生しました。しばらく時間をおいて再度お試しください。」＋ 再試行ボタン

### 5. 注文履歴画面

- 未認証ユーザーはログイン画面へリダイレクト
- ユーザーの注文一覧を新しい順に表示
- 各注文: 注文番号（数値）、注文日時、合計金額、ステータス
- ステータス色分け: 処理中（青）、配送済み（緑）
- ステータス集約ルール: 全sub_ordersが「配送済み」なら「配送済み」、それ以外は「処理中」
- アコーディオンで注文明細（商品名、数量、小計）を展開/折畳（全商品フラット表示、店舗別グルーピングなし）
- 店舗別ステータス詳細表示はスコープ外（将来拡張）
- 注文がない場合は空メッセージを表示
- ページネーション:
  - 1ページあたり10件表示
  - カーソルベース方式（注文ID指定）
  - APIパラメータ: `GET /orders?limit=10&lastOrderId={orderId}`
  - lastOrderIdは最後に取得した注文ID（数値）
  - バックエンド側で注文IDからDynamoDBのExclusiveStartKeyを組み立ててQueryする
  - フロントは「もっと見る」ボタンで次ページを追加読み込み
  - レスポンスのlastOrderIdがnullの場合はボタンを非表示

### 6. ログイン画面

- メールアドレス入力: 必須、形式バリデーション
- パスワード入力: 必須、表示/非表示トグル
- ログインボタン: ローディング状態あり
- 認証失敗時にエラーメッセージを赤色で表示
- JWT認証:
  - アクセストークンをlocalStorageに保持
  - 有効期限: 1時間
  - リフレッシュトークン: なし（ポートフォリオ規模のため簡素化）
  - 期限切れ時: 401レスポンスを検知しログイン画面へリダイレクト
- ログイン成功後、遷移元の画面へリダイレクト
- 認証状態をReact Contextでグローバル管理
